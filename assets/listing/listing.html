Generators: pages written from what you already produce

Leave the type out and LoreMaster recognises the format. If it cannot, it says so, instead of staying silent.

test-results

JUnit XML

A page per suite: cases, failures, stacks, totals.

coverage

Cobertura · LCOV

A page per folder with coverage bars, nested like the code.

openapi-docs

OpenAPI 3 · YAML or JSON

Operations by tag, parameters, responses, schemas.

storybook-docs

A page per component with real screenshots and props.

dart-docs

Classes, mixins, enums, extensions and functions.

Output is deterministic: the same inputs give the same bytes, so an unchanged report rewrites nothing.

In CI: the same engine, no editor

A single static binary per platform, attached to every release with a checksum.

# fetch the engine, verify it, run it
curl -fsSLO "$BASE/go-app-lore-master-engine-linux-amd64.zip"
sha256sum --check --ignore-missing lore-master-engine-$VERSION-sha256.txt
unzip go-app-lore-master-engine-linux-amd64.zip

# reports -> pages -> storage, in one command
lore-master-engine sync --generate --prepare --yes
# or only plan, to review a pull request
lore-master-engine sync --generate --dry-run --json
# a workflow step: docs beside your app
- uses: LoreMaster-App/LoreMaster/actions/pages@main
  with:
    out: dist/docs   # shown at <site>/docs/
- uses: actions/upload-pages-artifact@v4
  with: { path: dist }

# and a watch mode while you work
lore-master-engine watch --yes

Linux, macOS and Windows, on amd64 and arm64. Credentials come from the environment, never from the repository.
